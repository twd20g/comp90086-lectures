Part one

Inductive bias of CNNs

What a model assumes before it has seen any data.

Inductive bias

  • Most computer vision tasks have multiple possible solutions
    • Curse of dimensionality: images are large, often fewer training samples than dimensions
  • Most methods have relied on inductive bias
  • Inductive bias = an assumption or restriction that causes a machine learning algorithm to pick one solution over another
  • What are the inductive biases of a CNN?

Inductive biases of CNNs

  • Locality: the important features emerge from adjacent or nearby pixels (e.g. edges)
    • Features combine into more complex features, but every level of the hierarchy keeps this local property
  • Translation invariance (equivariance) — the model response should be the same no matter where in the image the feature is detected
Stacked 3×3 convolutions — what one output unit can see
layers 1
A 3×3 kernel makes the receptive field grow by 2 pixels per layer. Long-range structure is only reachable after many layers — locality is baked into the architecture, not learned.

Self-attention has a receptive field of the whole image at layer 1. That is the bias ViT gives up, and the reason it needs far more data to recover it.

Weaknesses of bag of features matching

  • Image patches are processed independently
  • No ability to respond to relationships between features
    • e.g. eye beside eye, above nose, above mouth ⇒ face
  • No memory of where each feature came from
Solution: Vision Transformers

Vision Transformers

grid
  • Split the image into N non-overlapping patches
  • Flatten each patch and pass it through a fully-connected layer → a patch embedding
    • Or take the embedding from a trained CNN
  • The input to the Transformer is a 1D sequence of patch embeddings
  • Interleave two kinds of information processing:
    • Passing information between patches
    • Processing information within each patch

Passing information: keys, queries and values

Attention head

Attention head

__EQ_ATTENTIONDARK__ __EQ_ATTENTIONLIGHT__
  • Transform the input patches into new vectors by comparing vectors derived from all pairs of patches
  • Called "attention" because the model can learn to weight certain pairs more than others
  • Note that patch order is irrelevant — permute the inputs and the outputs permute with them
  • The __EQ_SQRTDDARK____EQ_SQRTDLIGHT__ keeps the dot products from growing with dimension and saturating the softmax
  • Colours as on the diagram: queries, keys, values, softmax, output

Attention head parameters

  • The learned parameters are the weight matrices that map input embeddings to query, key and value vectors:
__EQ_QKVDARK__ __EQ_QKVLIGHT__
  • Multi-headed: each head learns its own Wq, Wk, Wv, so each head can learn a different relationship in the data, or perform a different task
  • Nothing in these parameters depends on n — the same head works for any number of patches
  • The shapes are forced by the diagram:
    • len(Query) = len(Key) — the width of Qᵀ must match the height of K, or the dot product is undefined
    • len(output) = len(Value) · N Queries = N outputs · N Keys = N Values

Summary

  • Model borrowed from NLP:
    • Treat the image as a "sentence" = a 1D sequence of patches
    • Use attention to learn relationships between pairs of patches
    • Can learn "features" from disconnected parts of the image
  • Removes some of the inductive bias of CNNs — and has to learn it back from data
Part three

Transformer results

Does removing the bias actually pay off?

Training Transformers

  • Transformers are even more prone to overfitting on small datasets than CNNs, and require more data than CNNs to learn generalisable features
  • ViT was pretrained on JFT-300M (300 million images) and fine-tuned for smaller datasets like ImageNet
  • This is the cost of the missing inductive bias: locality and translation equivariance are free in a CNN, and paid for in data in a ViT

Transformer results

Claim: Transformers outperform CNNs on very large scale datasets — and lose to them below ~100M images.
Dosovitskiy et al. (2021)

Transformers vs. CNNs

Claim: given an equal pretraining compute budget, ViT and CNN performance on ImageNet is the same.
Smith et al. (2023)

Transformers vs. CNNs

  • Transformers learn better on large-scale datasets
    • Unclear — may be equivalent when both models have the same computational budget
  • Transformers learn features that generalise better to new contexts
    • A common assumption, not yet rigorously tested
  • Much of the reported gap has turned out to be training recipe, not architecture

Inductive biases of ViTs

  • Positional encoding — whatever you choose is an assumption about which spatial relationships matter
  • Patch encoding — a fixed grid at a fixed scale, with hard boundaries
  • Some evidence of bias in what functions they learn; e.g. a preference for functions that ignore input order (Lavie, Gur-Ari & Ringel, 2024)
  • "No inductive bias" is never true — it is only ever different inductive bias

Patches as "words"

  • Simple but not ideal: ignores scale, and important information may be split across patches
  • Overlapping patches? Multiscale patches?
  • Adding patches is expensive: attention is O(N²) in the number of patches N
attention cost, 224×224 input
Halving the patch size quadruples the token count and so multiplies attention cost by ~16×. This is why the useful patch size bottoms out around 14–16 pixels, and why every follow-up architecture is really an attempt to buy finer patches more cheaply.

Problem with patches = "words"

  • Improvements on ViT have tried to improve patching without increasing computational complexity
  • Example: the Swin Transformer — attention inside local windows, with the windows shifted between layers so information still crosses boundaries
Liu et al. (2021)

Summary

  • Advantages of ViT over CNNs
    • Can efficiently learn features based on distant parts of an image
    • Might learn better features for generalisation
  • Disadvantages of ViT
    • Lacks the inductive biases of convolution (locality and translation invariance of features)
    • Simple non-overlapping patches can miss or obscure important features
    • Computational cost scales quadratically with the number of patches
