Why appearance is not enough

  • The same physical point looks different in each view — pose, lighting, scale
  • Points visible in one view may be missing from the other — occlusion, or simply out of frame
  • The background offers plenty of convincing impostors: patches that match well and mean nothing
  • A descriptor comparison alone will therefore produce a great many wrong answers. That is not a bug to tune away — it is the situation

We need geometry as well as features

  • What identifies an object is not just which features are present but also where they are relative to each other
  • A bag of matching patches is weak evidence. The same patches in the same spatial arrangement is strong evidence
  • So the question becomes: is there a single transformation that explains where all these matched points went?
Matching is a model-fitting problem

Model fitting, under hostile conditions

  • Propose a model that explains the correspondence between matched points, then find the points that fit it and measure how well
  • Two problems, and they are different:
    • Outliers — data the model does not explain at all. Most of your matches
    • Noise — data the model does explain, but imprecisely
  • Least squares handles noise and is destroyed by outliers: one bad correspondence drags the fit arbitrarily far
  • We need a fitting method whose answer does not depend on the wrong data at all

Key idea: data points vote for models

  • Let every data point vote for the models that are consistent with it, then take the model with the most support
  • Inliers agree with each other, so their votes pile up on the true model
  • Outliers disagree with each other as much as with the truth, so their votes scatter and cancel
  • Nothing is fitted to the outliers, so nothing is dragged by them
  • Hough transform and RANSAC are both this idea. They differ only in how they search the space of models
  • The model we finally want comes from 3D geometry, and is complicated — we will come to it
  • Both Hough and RANSAC are easier to see on a simpler model first: finding lines in an image
Part two

Hough transform

Voting by enumerating every model.

How would you find the lines?

Edge detection gives you points. Nothing in the edge map says which points belong to the same line.

Each point votes for the lines through it

  • A point in the image is consistent with infinitely many lines — every line through it
  • That set of lines is itself a line in parameter space. Points that lie on a common image line vote for a common point in parameter space

Noise, and the accumulator

  • With exact point locations the votes meet at a single point. With any noise at all they merely pass near each other, and there is no peak to find
  • Fix: quantise parameter space into bins and let points vote for bins. Nearly-agreeing votes now land in the same cell and accumulate
Figure: S. Savarese

Hough transform, live

Hough transform parameters

  • Bin size — too fine and votes for one line split across cells; too coarse and distinct lines merge
  • Peak threshold and number of peaks — how much support counts as a line, and how many you will accept
  • Minimum length and maximum gap — a peak says a line, not which segment of it; these recover the segments
  • Every one of these is a decision the method cannot make for you

The limit: cost grows with dimension

  • The Hough transform is an exhaustive grid search over parameter space. Every cell must exist, and every point must vote into it
  • Cost is exponential in the number of parameters:
    • line, 2 parameters — a grid of maybe 180 × 1000. Fine
    • circle (x, y, r), 3 — large, but tractable
    • homography, 8 — hopeless. Ten bins per parameter is 108 cells
  • And the transformation relating two views of a plane has exactly eight degrees of freedom
Enumeration becomes impossible — vote for one model instead
Part three

RANSAC

Voting without enumerating: let the data propose the models.

Let the data propose the models

  • RANdom SAmple Consensus. Points still vote for the model that explains them — but we never enumerate the models
  • Instead, sample the minimum number of points needed to generate one model, and count how many points agree with it
  • Repeat, and keep the model with the most agreement
  • Cost now depends on the fraction of outliers, not on the dimension of the parameter space — which is exactly what was killing the Hough transform

Summary

  • Recognising an instance means finding the same features in the same arrangement — a model-fitting problem where most of the data is wrong
  • Both methods answer it by voting, and differ only in how they search:
    • Hough enumerates parameter space — exhaustive, and limited to a few parameters
    • RANSAC samples data to generate models — cost set by the outlier rate, not the dimension
  • Applications: instance recognition, video stabilisation, panorama stitching, finding planes and vanishing points, 3D reconstruction
